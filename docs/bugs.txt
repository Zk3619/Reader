folo 文章历史似乎并没有强制登录？我在浏览器访问 folo web , 没登录，在订阅源预览页面能看到完整的历史文章记录，也可能预览下使用了内置账号？









是，主要原因是 **Folo 有云端历史数据库**，而 Reader 当前只抓订阅源此刻返回的 XML。

- Reader 分页本身没有总页数上限：单源每页 20 条、聚合每页 40 条，会一直读取本地 SQLite，直到本地数据耗尽。
- 但多数 RSS/RSSHub 接口一次只返回最近 10～100 条。Reader 新增订阅时只能入库这些内容，无法凭普通 RSS 获取更早文章。
- Folo 服务端长期定时抓取并积累历史条目；同一 feed 还可能早已被其他用户订阅，因此新用户也能分页看到大量云端历史数据。
- Reader 后续刷新不会删除旧文章，所以使用时间越长，本地历史也会逐渐累积。

因此当前看到的“滚动上限”通常是**本地已入库文章数量上限**，不是前端分页硬限制。

若希望接近 Folo，需要增加历史回填来源，例如：
1. RSSHub 路由支持分页时主动抓取多页；
2. 接入有历史归档的服务端 API；
3. 自建后台定时抓取并长期保存。

仅靠标准 RSS XML，通常无法补齐源站未返回的旧文章。

## Gopeed：对照 `gopeed-main`

### 已有 vs 缺失

| 能力 | 状态 | 说明 |
|------|------|------|
| HTTP 多连接 Range / `.part` | 部分 | `http.rs` 有；缺 slow-start、work-stealing、Method/Body |
| BT / Magnet / torrent | 桩 | 能解析；无 peer 下载；webseed 偶发回退 HTTP |
| ED2K | 桩 | **仅解析**；传输明确未启用 |
| 任务生命周期 | 部分且断线 | 见下方 IPC |
| 解压 zip/7z/rar… | 缺失 | TS 有壳，Rust **无** `extract_archive` |
| Webhook / 完成脚本 | 部分 | 有基础实现；设置/链路不完整 |
| 代理 system/custom | 桩 | 配置字段存在，引擎**未接线** |
| 扩展机制 | 桩～部分 | 有 manifest/match/git 安装骨架；缺 goja 级 polyfill、WebView、升级、settings 表单 |
| Flutter 级 UI | 部分 | 四页壳；无 history、无 BT 文件树 |

### 关键断线（已核实）

TS 调用的命令与 Rust 注册**不一致**：

| TS 调用 | Rust 实际 |
|---------|-----------|
| `download_engine_start`（[`queue.ts`](d:\Projects\Reader\src\lib\download\gopeed\queue.ts)） | 只有 `download_engine_create` |
| `download_engine_extract_archive` | **不存在** |
| `download_engine_copy_extension` | **不存在** |
| `eval_js` 期望 `{ result, storage }` | 实际返回 `String` |

因此即便 HTTP 引擎本身可用，**TS 队列启动路径当前是断的**。

## 一句话

- **Gopeed**：不是完整兼容；HTTP 核最接近，BT/ED2K/解压/代理/扩展生态远未达标，且存在 **IPC 断线**。  
- **yt-dlp**：**注册表 ≠ 全站点能力**；全站 URL 能挂名，真实提取只有 YT/B 站/Generic，整体不能替代 yt-dlp。

若要继续逼近验收口径，建议优先修：**队列 `create` IPC 对齐 → HTTP 端到端可用 → 扩展 eval 契约 → 再按站点优先级移植 `_real_extract`（而非只扩 registry）**。需要的话我可以按这个缺口清单排一版补齐计划并直接开工。
