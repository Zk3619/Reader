结合 Reader 里现有实现（`VirtualChapterList`、缓存页的 `VirtualBookshelfCacheGrid`，其余页多为 `<For>` + CSS Grid），建议**不要全部虚拟化**，而是按「数据量 × DOM 复杂度 × 交互约束」分层处理。

## 判断原则（简要）

| 因素 | 倾向虚拟列表 | 倾向常规列表 |
|------|-------------|-------------|
| 常见条数 | 稳定 >150～200 | 通常 <50～100 |
| 行高 | 固定或可按「行」估算 | 简介/徽章导致行高不定 |
| 交互 | 仅点击、滚动加载 | Sortable 拖拽、复杂多选与 DOM 强绑定 |
| 卡片 | 封面 + 少量文本（可 `loading="lazy"`） | 可展开面板、嵌套子列表 |

项目里的 `VirtualChapterList` 是**固定行高**虚拟滚动；多列网格应像缓存页那样**按行虚拟化**（`VirtualBookshelfCacheGrid`），而不是对每个卡片单独虚拟。

## 分页面建议

### 常规列表就够（不必优先做虚拟）

| 页面 | 理由 |
|------|------|
| **分组页** `BookGroup` | 分组数量通常几十以内；有 Sortable 拖拽；卡片样式多但总量小。 |
| **分组管理页** `BookGroupManage` | 同上，且必须保留 Sortable 与完整 DOM 顺序。 |
| **书源页** `SourcesPage`（默认分组折叠结构） | 结构是「分组块 + 可展开项 + 发现子区」，不是扁平长列表；单组内书源再多，也常被折叠挡住，全页虚拟收益有限、实现成本高。 |

### 已适合 / 应保留虚拟列表

| 页面 | 现状与建议 |
|------|-----------|
| **缓存页** `BookshelfCachePage` | 已用 `VirtualBookshelfCacheGrid`，固定行高（64px），合适。 |
| **阅读器目录** `ReaderCatalog` | 已用 `VirtualChapterList`，章节可达数千，必须虚拟。 |
| **搜索范围对话框** 等长 checkbox 列表 | 已虚拟，合理。 |

### 建议引入虚拟（优先级高）

| 页面 | 理由 |
|------|------|
| **探索书源内容区** `ExploreSourcePageContent` | 滚动加载会累积数百条；卡片布局与 `EXPLORE_BOOK_GRID_CLASS` 固定，和缓存页同一套「按行虚拟」最合适。 |
| **搜索页 — 在线结果** `BookSearchPage` | 结果持续追加，DOM 会线性增长；卡片与探索页一致，可复用同一虚拟网格组件。 |

### 条件性虚拟（中等优先级，需分支）

| 页面 | 建议策略 |
|------|----------|
| **书架页** `BookShelf`（分组内书籍） | **手动排序时：必须常规列表**（Sortable 依赖真实 DOM）。**非手动排序且书籍数 > 阈值（约 150～200）**：网格/紧凑列表可虚拟；标准列表若带可变高度简介，需固定行高或单独算行高，否则先不虚拟。 |
| **书架管理页** `BookshelfManagePage` | 无 Sortable，但有多选 checkbox；全量书很多时值得虚拟；可与书架共用「按行网格虚拟」，阈值同上。 |
| **搜索页 — 本地书架匹配** | 上限=书架总量；书多时可与在线区共用组件 + 阈值开关。 |

### 书源页的特殊说明

- **按分组折叠展示**：维持常规列表即可。
- 若存在「平铺全部书源、无折叠」且单屏可见项很多，可只对**扁平模式**做虚拟；与 Sortable/展开态并存时要单独设计，不建议与分组页一刀切。

---

## 不建议「全部虚拟列表」

1. **Sortable 冲突**：书架/分组在拖拽排序时必须保留完整 DOM（代码里也已说明 Sortable 与 Solid 重渲染的坑）。
2. **小列表反而更差**：分组、分组管理、搜索历史 chip 等，虚拟化有测量/回收开销，收益接近零。
3. **行高不统一**：书架多种 `ViewMode`（列表 1～3 列、网格 2～8 列、封面叠字、简介行）若强行用当前固定行高虚拟，容易裁切或留白；要么统一行高，要么上动态高度虚拟库（成本明显更高）。
4. **封面懒加载**：探索/书架卡片已有 `loading="lazy"`，中等规模（一两百本）常规列表往往可接受；瓶颈通常在**上千节点 + 滚动加载累积**。

## 推荐落地顺序（若要做）

```mermaid
flowchart LR
  A[已有: 目录 + 缓存页] --> B[探索列表 + 搜索在线结果]
  B --> C[书架/管理: 非手动排序 + 阈值]
  C --> D[书源页仅扁平大列表可选]
```

1. 抽出通用组件：如 `VirtualExploreBookGrid`（基于 `VirtualBookshelfCacheGrid` + `EXPLORE_BOOK_GRID_CLASS` + 探索卡片行高常量）。
2. 用于 `ExploreSourcePageContent`、`BookSearchPage` 在线结果区。
3. 书架 `BooksGrid`：`sortMode !== 'manual' && books.length > N` 时走虚拟网格；`manual` 始终 `<For>`。
4. 分组相关页保持常规列表。

## 一句话结论

- **不必全部虚拟**；分组/分组管理/书源折叠视图用常规列表即可。  
- **必须/已做虚拟**：章节目录、缓存页。  
- **下一批最值得做**：探索列表、搜索在线结果（滚动累积、布局固定）。  
- **书架与书架管理**：仅在大数量且非手动排序时按行虚拟；手动排序模式继续常规列表。

若你希望统一实现，我可以按上述优先级在 `ExploreSourcePageContent` 和 `BookSearchPage` 先抽共用虚拟网格，并给书架加一个 `books.length` 阈值开关。
